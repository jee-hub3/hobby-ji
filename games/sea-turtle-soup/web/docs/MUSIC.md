# 음악 설계서 「김 서린 유리」

바다거북 스프의 배경음악 기획과 설계입니다. 엔지니어가 이 문서만 보고 그대로 만들 수 있게 썼습니다.

- 적용 대상: 웹 서비스판 `web/public/index.html`, claude.ai 아티팩트판 `index.html` (두 페이지 모두)
- 구현: `web/public/music.js` 한 파일. 샘플, 외부 파일, 의존성 없이 Web Audio로 그 자리에서 만들어 냅니다.
- 원칙: 이 작업 환경에서는 아무도 소리를 들을 수 없습니다. 그래서 음악에 대한 약속은 모두 8장의 측정값으로 확인합니다.
  아래 숫자는 이 레시피를 OfflineAudioContext 프로토타입으로 렌더링하고 ffmpeg ebur128과 numpy로 재 본 뒤에 정했습니다(부록 A).

## 1. 콘셉트

「밤의 카운터」의 음악은 곡이라기보다 그 가게의 공기입니다. 펜던트 조명 아래 카운터에서는 육수 냄비가 낮게 끓고,
유리창에는 김이 서려 바깥 불빛이 번집니다. 어딘가에서 따뜻한 화음이 아주 느리게 바뀌고, 가끔 건반 한두 음이 물방울처럼 떨어졌다가
리버브 속으로 사라집니다. 플레이어는 한 시간 동안 긴 한국어 장면을 읽고 질문을 쓰므로, 음악은 읽기를 방해하지 않는 배경이어야 합니다.
의식하지 않으면 잊히고, 멈추면 빈자리가 느껴지는 정도를 목표로 합니다. 늦은 밤 재즈 클럽의 마지막 셋, Nils Frahm이나 Ólafur Arnalds 같은
절제된 피아노 앰비언트, 그리고 볼륨을 한껏 낮춘 시티팝 라디오의 색을 참고했습니다.

## 2. 음악 언어

### 2.1 조성, 조율, 음역

- 중심음은 **Db**입니다. 뼈대는 Db 장조 펜타토닉(Db Eb F Ab Bb)이고, 화음에 따라 C, Gb, 그리고 메뉴판에서만 G(리디안 #11)를 색으로 더합니다.
- 이렇게 고른 이유: Db 장조의 maj9 계열은 늦은 밤 재즈 발라드의 대표 색입니다. 또 아래 모든 화음이 **Db 페달 위에서 부딪히지 않도록** 골랐기 때문에,
  플레이 중에는 베이스를 한 번도 움직이지 않을 수 있습니다. 에너지가 가장 낮은 상태입니다.
- 조율은 A4 = 440 Hz 평균율입니다. `f = 440 * 2^((m - 69) / 12)`, m은 MIDI 번호입니다.

| 레이어 | 최저 | 최고 |
| --- | --- | --- |
| 드론 (기음) | Db2 = 37, 69.30 Hz | Bb2 = 46, 116.54 Hz (메뉴판에서 루트를 따라갈 때만) |
| 패드 | Eb3 = 51, 155.56 Hz | Ab4 = 68, 415.30 Hz |
| 건반 | Eb4 = 63, 311.13 Hz | Ab5 = 80, 830.61 Hz |
| **전체** | **Db2 69.30 Hz** | **Ab5 830.61 Hz** (기음 기준. 배음은 필터로 깎음) |

### 2.2 화음 어휘와 보이싱

패드는 4성부입니다. 화음마다 보이싱 A(확률 0.7)와 B(0.3)가 있어 같은 화음이 돌아와도 모양이 조금 다릅니다.
건반 풀은 그 화음 위에서 건반이 고를 수 있는 음이고, 장면 음역(2.6)으로 한 번 더 거릅니다.

보이싱 규칙(위 표는 모두 만족하고, 테스트 D10이 확인합니다):
- 이웃 성부 사이에 단2도(반음)를 두지 않습니다.
- 장2도는 아래 음이 Ab3(56) 이상일 때만 허용합니다. 낮은 음역의 2도는 탁하게 울립니다.
- 패드 음은 모두 Eb3(51)과 Ab4(68) 사이에 있습니다.

### 2.3 화성 리듬과 진행

- 화음 길이(새 화음이 들어온 뒤 릴리스가 시작될 때까지)는 장면별 범위에서 **삼각분포**로 뽑습니다: `a + (b - a) * (r() + r()) / 2`.
  플레이 18–30초, 메뉴판 12–20초, 완식 14–22초, 포기 18–28초.
- 화음 교대는 동일 전력 크로스페이드입니다. 다음 화음이 sin 곡선으로 6초 동안 들어오고, 바로 그 순간 이전 화음이 cos 곡선으로 7초 동안 빠집니다.
- 진행은 가중치 마르코프 표로 고릅니다. 같은 화음이 연달아 나오지 않습니다(자기 전이 없음).

플레이·메뉴판 전이표:

| 현재 | 다음 후보 (가중치) |
| --- | --- |
| `I` | `IV` .35, `vi` .30, `ii` .20, `iii` .15 |
| `IV` | `I` .40, `ii` .25, `vi` .20, `V` .15 |
| `ii` | `V` .35, `IV` .25, `I` .20, `vi` .20 |
| `iii` | `vi` .40, `IV` .35, `ii` .25 |
| `V` | `I` .45, `vi` .30, `IV` .25 |
| `vi` | `IV` .40, `ii` .30, `iii` .15, `I` .15 |

완식 전이표(장조 색만): `I` → `IV` .5, `I69` .3, `vi` .2 / `IV` → `I` .6, `I69` .4 / `I69` → `IV` .5, `vi` .3, `I` .2 / `vi` → `IV` .7, `I69` .3

포기 전이표(으뜸화음으로 돌아오지 않음): `vi` → `IV` .5, `ii` .5 / `IV` → `vi` .5, `ii` .5 / `ii` → `vi` .6, `IV` .4

반복 방지 제약:
- (화음 id, 보이싱) 3개 연쇄가 최근 180초 안에 나왔던 것과 같아지는 후보는 가중치를 0.2배로 줄이고 한 번 다시 뽑습니다.
- 평상 장면에서 화음 교대 사이 간격은 최소 10초입니다. 큐 시퀀스(4.4, 4.5)는 예외입니다.

### 2.4 건반: 제약 있는 랜덤 워크

건반은 제스처 단위로 움직입니다. 제스처는 1–3음의 짧은 덩어리이고, 제스처 사이에는 긴 쉼이 있습니다.

1. **제스처 간격**: 이전 제스처의 마지막 음에서 다음 제스처까지 장면별 범위(2.6)에서 균등분포로 뽑습니다. 플레이는 8–22초입니다.
2. **음 수**: 장면별 확률로 1, 2, 3음을 뽑습니다. 플레이는 0.6 / 0.3 / 0.1입니다.
3. **제스처 안 간격**: 음과 음 사이는 U(0.7, 1.6)초입니다.
4. **음높이**: 현재 화음의 건반 풀을 장면 음역으로 거른 오름차순 목록에서 인덱스를 걷습니다.
   - 걸음 확률: -2: .15, -1: .30, 0: .10, +1: .30, +2: .15
   - 같은 방향 걸음이 2번 이어졌으면 세 번째 걸음은 부호를 뒤집습니다. 음계처럼 오르내리는 선율이 생기지 않게 하는 규칙입니다.
   - 목록 끝에서는 안쪽으로 고정합니다(clamp). 중앙에서 3칸 넘게 벗어나면 중앙 방향 걸음 가중치를 2배로 줍니다.
   - 같은 음은 두 번까지만 연속으로 칠 수 있습니다.
   - 화음이 바뀌면 직전 음과 가장 가까운 새 풀의 음으로 옮깁니다. 거리가 같으면 아래 음을 고릅니다.
   - 음형 방지: 최근 300초의 4음 음형(음높이 4개 연쇄)과 같아지는 후보는 최대 4번 다시 뽑고, 그래도 같으면 그 음을 쉽니다.
5. **세기**: v = U(장면 범위) × [1, 0.8, 0.7][제스처 안 순서]. 덩어리 안에서 뒤의 음이 앞의 음보다 커지지 않게 합니다.
6. **겹음**: 0.12 확률로 지금 음과 풀에서 두 칸 위 음을 30 ms 차이로 함께 칩니다. 위 음의 세기는 v × 0.6이고, 두 음은 단3도 이상 떨어져야 합니다.
7. **쉼 구간**: 플레이에서는 180–360초마다 40–70초 동안 건반이 완전히 쉽니다. 귀를 쉬게 하는 구간입니다.

### 2.5 무작위 원천

- PRNG는 mulberry32입니다. 시드에서 서로 독립된 흐름을 만들어, 한 레이어를 고쳐도 다른 레이어의 결과가 바뀌지 않게 합니다.
  화성 `seed*7919+1`, 건반 `+2`, 공기 `+3`, 보이싱 `+4`, 리버브 임펄스 `seed*31+11+ch`, 노이즈 버퍼 `seed*101+layer`.
- 실서비스 시드는 페이지를 열 때마다 새로 뽑습니다: `(Date.now() ^ (Math.random() * 2**32)) >>> 0`. 분석과 테스트는 시드 1, 2, 3을 고정해서 씁니다.

| 공기 | texBus -34.8 dB | -14 dB | 넓게(비상관 L/R) | 가게의 공기. 의식되지 않는 높이 |
| 마스터 trim | `MASTER_TRIM_DB = +2.9` | | | 보정값. 5.1의 플레이 목표에 맞춥니다 |

솔로 렌더 균형 목표(플레이, 자정, 시드 1, 전체 믹스 통합 음량 대비): 패드 -1.3 ±1.0 LU, 드론 -8.0 ±1.5, 건반 -8.0 ±1.5(게이트 적용 통합값), 공기 -12.5 ±1.5.
엔지니어는 각 레이어를 따로 렌더링해 이 균형을 먼저 맞추고, 그다음 `MASTER_TRIM_DB` 하나로 전체 음량을 맞춥니다.

### 3.3 패드 (warm pad bed)

- 파형: `ctx.createPeriodicWave(real, imag)`, `real` 전부 0, `imag[0] = 0`, n = 1..12에서 `imag[n] = (n 홀수 ? 1.0 : 0.6) / n^1.5`.
  정규화는 기본값을 씁니다(disableNormalization: false). 홀수 배음을 조금 더 둔 둥글고 속이 빈 따뜻한 소리입니다.
- 성부 하나에 오실레이터 2개:
  - 주 오실레이터: detune U(-1, +1) cents, 진폭 1.0
  - 짝 오실레이터: detune +7 cents + U(-1, +1), 진폭 **0.15**
  - 짝을 같은 크기로 두지 않는 이유: 같은 크기의 두 음은 100% 맥놀이를 만들어 400 ms 순간 음량이 4–6 LU씩 출렁입니다(프로토타입 실측 4.6 LU).
    0.15로 두면 반짝임은 남고, 짝이 더하는 출렁임은 0.3 LU 안으로 줄어듭니다(짝이 없을 때 2.6 LU, 있을 때 2.9 LU).
- 성부 게인: `0.03 × dB(0, -1, -2, -3.5)`(낮은 성부부터). 윗성부일수록 작게 해 밝음을 누릅니다. 각 성부는 StereoPanner로 -0.45, -0.15, +0.15, +0.45에 둡니다.
- 화음 엔벨로프(화음마다 GainNode 하나): 0에서 시작해 `setValueCurveAtTime(sin 곡선 64점, t, 6)`으로 1.0까지 오르고, 서스테인 1.0,
  릴리스 시각부터 `setValueCurveAtTime(cos 곡선 64점, tr, 7)`로 내려갑니다. 오실레이터는 릴리스 끝 + 0.1초에 stop하고 onended에서 disconnect합니다.
- 와우(테이프 흔들림): 공유 사인 LFO 0.07 Hz, 깊이 ±2 cents를 모든 패드 오실레이터의 detune에 연결합니다.
- padIn(장면 게인): menu 0 dB, play -2, thinking -2, solved -0.5, gaveup -2.
- 필터: BiquadFilter lowpass 2단(합쳐서 24 dB/oct), Q 0.5, 공진 없음.
  컷오프 = 장면 기준(menu 1100, play 850, thinking 850, solved 1000, gaveup 800 Hz) × 테마(자정 0.88, 오후 1.0).
  사인 LFO 1/77 Hz가 기준값의 ±15%로 두 필터의 frequency를 함께 흔듭니다.

### 3.4 드론 (low drone)

- 사인 2개: 루트(진폭 1.0)와 한 옥타브 위(0.35). 각각 진폭 LFO를 따로 둡니다(사인 0.011 Hz와 0.017 Hz, 깊이는 자기 진폭의 ±16%, 약 ±1.4 dB).
- 엔벨로프: 어택 8초 sin 곡선, 릴리스 8초 cos 곡선.
- play, thinking, solved, gaveup에서는 Db2 페달이 끊기지 않고 이어집니다. menu에서는 화음 루트를 따라가며, 루트가 바뀔 때 8초 크로스페이드로 넘깁니다.
- 가운데 모노, droneBus -39 dB, 리버브 send -18 dB.
- 근거: 69 Hz는 휴대폰 스피커로는 들리지 않습니다. 이어폰에서는 방의 바닥이 되고, 휴대폰에서는 옥타브 배음(138.6 Hz)과 패드가 그 몫을 합니다.
  드론 솔로가 믹스보다 8 LU 낮아서 웅웅거리지 않습니다. 저역 비율 목표(S4)가 이를 지킵니다.

### 3.5 건반 ("펠트 로즈", 부드러운 2-op FM)

- 캐리어: 사인, 주파수 f. 모듈레이터: 사인, 주파수 f(비율 1:1). 모듈레이터 → GainNode(index) → `carrier.frequency`.
- 변조 지수: 시작값 `I0 × f`, `I0 = 0.8 + 0.8 × v`. 그 뒤 `setTargetAtTime(0.15 × f, t, 0.35)`로 줄어듭니다.
  치는 순간에만 따뜻한 배음이 잠깐 붙고 곧 사인에 가까운 음이 됩니다. 종소리 같은 고배음 비율(예: 14:1)은 쓰지 않습니다.
- 음마다 저역통과: lowpass, cutoff `min(2200, 4.5 × f)` Hz, Q 0.3.
- 음량 엔벨로프(펠트 해머):
  - `setValueAtTime(0, t)` → `linearRampToValueAtTime(peak, t + 0.020)` (어택 20 ms)
  - `setTargetAtTime(0.55 × peak, t + 0.020, 0.15)`
  - `setTargetAtTime(0.0001, t + 0.45, 2.2)`
  - 노트 오프: `setTargetAtTime(0, t + 4.2, 0.6)`. 오실레이터는 t + 8.2에 stop하고 onended에서 disconnect합니다.
- `peak = v^1.5`. C5(72)보다 높은 음은 여기에 ×0.708(-3 dB)을 곱합니다.
- 팬: `clamp((m - 69) / 12 × 0.35 + U(-0.1, 0.1), -0.45, 0.45)`. 피아노처럼 낮은 음은 왼쪽, 높은 음은 오른쪽입니다.
- 동시 발음은 최대 8음입니다. 넘치면 가장 오래된 음을 `setTargetAtTime(0, now, 0.1)`로 줄이고 0.5초 뒤 stop합니다.
- keysBus -24.4 dB. 리버브 send는 자정 -2 dB, 오후 -4 dB입니다. 밤에는 음이 방 안으로 더 번집니다.

### 3.6 공기 (ambience texture)

노이즈 버퍼는 모두 **모노**이고 시드로 만듭니다. 끝 0.5초는 앞 0.5초와 선형 크로스페이드해서 루프 이음새를 없앱니다.
레이어마다 같은 버퍼에 AudioBufferSourceNode 두 개를 걸어 L은 오프셋 0, R은 오프셋 `len / 2`에서 시작하고 ChannelMerger로 합칩니다.
메모리는 모노 하나로 쓰면서 비상관 스테레오를 얻는 방법입니다. 각 소스의 playbackRate는 U(20, 40)초마다 U(0.98, 1.02)로 선형 램프하며 표류하므로,
같은 샘플 구간이 같은 모양으로 돌아오지 않습니다.

| 층 | 노이즈 | 버퍼 길이 | 필터 | 게인 | 움직임 |
| --- | --- | --- | --- | --- | --- |
| 김 (냄비에서 오르는 김) | 핑크: `b0=.99765*b0+w*.0990460; b1=.96300*b1+w*.2965164; b2=.57000*b2+w*1.0526913; out=(b0+b1+b2+w*.1848)*0.2` | 12.7 s | bandpass 700 Hz Q 0.5 → lowpass 2200 Q 0.5 → lowpass 2200 Q 0.5 | 0 dB | 숨: U(9, 15)초마다 목표 U(-3, 0) dB, `setTargetAtTime` τ 3 s |
| 방 (가게의 낮은 울림) | 브라운: `br=(br+0.02*w)/1.02; out=3.5*br` | 7.3 s | lowpass 300 Hz Q 0.5 | -6 dB | 고정 |
| 밤비 (유리창의 빗소리, 자정 테마 전용) | 화이트 × 0.5 | 9.1 s | highpass 900 Hz Q 0.5 → lowpass 2600 Q 0.5 ×2 | -4 dB | U(15, 30)초마다 목표 U(-2, 0) dB, τ 5 s. 오후 테마에서는 8초에 걸쳐 0으로 |

- texBus -34.8 dB, 리버브 send -14 dB.
- 빗방울 소리는 넣지 않습니다. 빗방울은 그 자체가 타악기 트랜지언트이기 때문입니다. 비는 유리 너머로 들리는 낮은 쉬-소리로만 둡니다.

### 3.7 리버브 (생성 컨볼루션 임펄스)

- 길이 3.5초, 스테레오. 채널마다 독립된 시드 화이트 노이즈를 씁니다.
- 프리딜레이 25 ms: 앞부분을 0으로 채웁니다.
- 감쇠: 진폭 `exp(-6.9078 × (t - 0.025) / 3.4)`, 즉 RT60 3.4초입니다.
- 댐핑(시간이 갈수록 어두워짐): 노이즈에 one-pole 저역통과를 걸고 컷오프를 `fc(t) = 5000 × (1200/5000)^(t/3.5)` Hz로 내립니다. 계수는 `a = 1 - exp(-2π fc / sr)`, `y += a × (x - y)`.
- 프리딜레이 뒤 10 ms 선형 페이드인, 마지막 200 ms 선형 페이드아웃.
- 정규화: 채널마다 에너지 합(Σx²)이 1이 되게 맞춥니다. `ConvolverNode.normalize = false`는 buffer를 넣기 **전에** 설정합니다. 그래야 send 레벨이 표의 값 그대로 동작합니다.
- 입력: `rvIn` GainNode를 `channelCount = 1`, `channelCountMode = 'explicit'`로 둡니다. 모노로 합쳐서 넣으면 컨볼루션 계산이 절반으로 줍니다.
- 리턴: highpass 140 Hz → lowpass 4000 Hz(둘 다 Q 0.707) → masterIn, 0 dB.
- 딜레이(메아리)는 쓰지 않습니다. 반복되는 메아리는 그 자체로 박과 작은 루프를 만들어 금지 목록에 걸립니다. 공간감은 리버브로 충분합니다.

### 3.8 마스터

- highpass 30 Hz Q 0.707: DC와 초저역을 막습니다.
- lowpass 7 kHz Q 0.5: 고역 안전장치입니다.
- trim `MASTER_TRIM_DB` (시작값 +2.9 dB): 보정값입니다.
- userVol: 0–1, 기본 1.
- fade: 시작, 탭 전환, 켜고 끄기에 씁니다.
- 컴프레서와 리미터는 쓰지 않습니다. DynamicsCompressorNode는 자동 메이크업 게인을 더해서 음량을 예측할 수 없게 만듭니다. 헤드룸은 측정으로 지킵니다(트루 피크 -10 dBTP 이하, 실측 -16 안팎).

## 4. 장면 설계

### 4.1 장면 판별 (DOM 관찰)

모듈은 게임 코드를 고치지 않습니다. 아래 훅만 읽습니다.

```js
const vis = el => !!el && !el.hidden && !el.closest('[hidden]');
function sceneNow() {
  if (vis($('#reveal'))) return vis($('#rv-seal')) ? 'solved' : 'gaveup';
  if (vis($('#play-view'))) return document.querySelector('#log .pending') ? 'thinking' : 'play';
  return 'menu';
}
```

- 관찰 대상:
  - `#menu-view`, `#play-view`, `#reveal`, `#rv-seal`의 `hidden` 속성
  - `#log`의 childList와 subtree, class 속성
  - `<html>`의 `data-theme`
  - `matchMedia('(prefers-color-scheme: dark)')` change 이벤트
- 판정은 마지막 변경 뒤 **250 ms가 조용해지면** 한 번만 합니다. 게임은 한 동작에서 DOM을 여러 단계로 바꾸므로 중간 상태를 듣지 않기 위함입니다.
  예를 들어 마지막 장을 풀면 장 카드 추가와 결말 창 열기가 같은 틱에 일어납니다.
- 테마: `data-theme`이 있으면 그 값(`dark`면 자정)을 쓰고, 없으면 `prefers-color-scheme`을 따릅니다. 게임의 `effectiveDark()`와 같은 규칙입니다.
- 퍼즐 키: `#p-no` 글자 + `|` + `#p-title` 글자. 두 페이지 모두에 있지만 보조 장치로만 씁니다. 없으면 빈 문자열입니다.

**장 해결 큐 판정**(아래를 모두 만족할 때 `cue('chapter')`):
1. 직전 판정과 지금 판정의 장면이 모두 `play` 또는 `thinking`이다.
2. 퍼즐 키가 직전과 같다.
3. `#log .entry-chapter` 개수가 직전보다 정확히 1 늘었다.
4. 이번에 플레이 화면이 보이기 시작한 지 1.5초가 지났다. 이어 하기로 열 때 이미 있던 장 카드는 큐가 아닙니다.
5. 같은 판정에서 결말 창이 열리지 않았다. 마지막 장이면 완식 시퀀스가 대신합니다.
6. 직전 장 해결 큐로부터 20초가 지났다(쿨다운).

넘긴 장도 장 카드를 만들므로 같은 숨결이 나옵니다. 이 숨결은 승리의 팡파르가 아니라 "다음 장이 열린다"는 뜻이라 두 경우 모두에 맞습니다.

### 4.2 전환과 크로스페이드

모든 음악 파라미터는 같은 방식으로 바꿉니다.

```js
param.cancelScheduledValues(T);
param.setValueAtTime(trackedValue(param, T), T);
param.setTargetAtTime(target, T, xfade / 3);
```

`setTargetAtTime`은 3τ, 즉 xfade 시간에 95%에 닿습니다. `trackedValue`는 엔진이 자바스크립트에서 계산해 둔 그 시각의 값입니다(7.5).

| 전환 | xfade | 화음 처리 |
| --- | --- | --- |
| menu → play | 8 s | 지금 화음의 릴리스가 T + 8초보다 늦으면 T + U(4, 8)초로 당기고, 그다음부터 플레이 어휘와 길이를 씁니다. 드론은 8초에 걸쳐 Db2 페달로 갑니다 |
| play → menu | 8 s | 같은 규칙. 드론은 다음 화음부터 루트를 따라갑니다 |
| play ↔ thinking | 없음 | 파라미터는 그대로 두고 건반 새 음만 막습니다. 이미 울리는 음은 자연 감쇠합니다. 생각이 끝나면 최소 4초 뒤에야 다음 제스처가 옵니다. 답이 오는 순간 음이 울리지 않게 하기 위함입니다 |
| → chapter 큐 | 시퀀스 (4.4) | |
| play → solved | 시퀀스 (4.5) | 퍼즐마다 페이지당 한 번. 다시 열기는 6초 크로스페이드만 |
| play → gaveup | 6 s (4.6) | 같은 규칙 |
| solved/gaveup → menu | 8 s | |
| solved/gaveup → play ("닫고 기록 보기") | 8 s | |
| 테마 전환 (오후 ↔ 자정) | 8 s | 패드 컷오프 배수, 밤비 게인, 건반 send만 바뀜 |

**빠른 연속 변화**:
- 판정은 250 ms 정착 뒤에만 합니다. 메뉴판과 플레이를 2초 안에 오가면 엔진은 매번 지금 값에서 새 목표로 다시 향합니다. 대기열이 없어서 쌓이지도 튀지도 않습니다.
- 큐 시퀀스가 도는 중에 장면이 바뀌면 남은 **파라미터** 자동화를 취소하고 새 장면 목표로 다시 향합니다. 이미 시작한 화음은 새 경계에서 정상 릴리스됩니다.
- 패드 화음은 동시에 3개까지만 둡니다. 넘치면 가장 오래된 화음을 3초 cos로 내립니다.
- 장 해결 큐 쿨다운은 20초입니다. 결말 도입 시퀀스는 (퍼즐 키, 결말 종류)마다 페이지당 한 번만 나옵니다.
- 엔진에 들어가는 시각이 이미 생성된 구간(최대 1.5초 앞) 안이면 화성과 건반 변화는 그 구간 끝으로 미룹니다. 크로스페이드가 3초 이상이라 이 지연은 들리지 않습니다.

| --- | --- | --- |
| menu | 맞이하는 따뜻함. 손님이 들어와 메뉴판을 볼 때 | 화음이 조금 더 자주 바뀌고(12–20초), 리디안 색(`IL`)이 섞이고, 드론이 루트를 따라 움직이고, 건반이 약 11음/분. 플레이보다 +1.5 LU |

| thinking | 밴드가 숨을 죽이는 정도. 거의 차이 없음 | 건반 새 음만 멈춤. 파라미터는 그대로. 매 질문마다 소리가 출렁이면 한 시간에 100번 넘게 반복되는 패턴이 되므로 일부러 들리지 않게 했습니다 |

### 4.4 장 해결: 숨결 (T = 장 카드가 생긴 시각)

| 시각 | 일 |
| --- | --- |
| T | 지금 화음이 4초 cos 릴리스를 시작. `V`(Ab9sus4, 보이싱 A)가 3초 sin으로 들어와 4초 유지, 4초 릴리스 |
| T → T+3 | padIn을 장면값보다 +3 dB까지 선형 상승. 공기를 -3 dB까지 선형 하강(김이 걷히는 느낌) |
| T → T+4 | 패드 컷오프를 기준 × 1.6까지 선형 상승 |
| T+4 | `I69`(Db6/9)가 4초 sin으로 들어와 12초 유지, 7초 릴리스. 건반 겹음 하나: {F4+Bb4, Ab4+Eb5, Bb4+Eb5} 중 하나, 아래 음 v 0.5, 위 음 +40 ms에 v 0.32 |
| T+5 → T+10 | padIn을 장면값으로 선형 복귀 |
| T+4 → T+10 | 컷오프 복귀 |
| T+6 → T+11 | 공기 복귀 |
| T → T+12 | 평소 건반 제스처 없음 |
| T+16 | `I`(Dbmaj9)에서 평소 화성 산책 재개 |

드론(Db 페달)은 건드리지 않습니다. 베이스가 움직이지 않아 해결이 "쾅" 하고 닫히지 않습니다.
목표(8.2 C1–C3): 숨결 최고점은 직전 바탕보다 +1.5–4.0 LU(시드 1–5 중앙값 +2.0–3.5), 최고점은 T+3–9초, T+12–22초에는 바탕 ±2 LU 안으로 돌아옵니다.

### 4.5 완식: 따뜻한 해결 (T = 결말 창이 열리고 `#rv-seal`이 보인 시각)

| 시각 | 일 |
| --- | --- |
| T | 지금 화음이 4초 cos 릴리스. `V`(A)가 3초 sin으로 들어와 5초 유지, 5초 릴리스. 공기는 6초에 걸쳐 -2 dB로 |
| T+2 → T+7 | padIn을 solved 바탕값(-0.5 dB) + 3 dB까지. 컷오프를 play 기준 × 1.6까지 |
| T+5 | `I`(Dbmaj9, A)가 5초 sin으로 들어와 10초 유지, 7초 릴리스. 건반 겹음: `I` 풀의 F4–Eb5 안에서 5 또는 7반음 떨어진 두 음, v 0.5 / 0.32 |
| T+10 → T+17 | padIn을 -0.5 dB로, 컷오프를 solved 기준(1000 × 테마)으로 |
| T+12 | solved 건반 시작 |
| T+15 | `I69`가 6초 sin으로 들어오고, 그 뒤 완식 전이표로 산책 |

`완주`(넘긴 장이 있는 해결)도 같은 시퀀스를 씁니다.
목표(C4–C5): 해결 최고점은 직전 바탕보다 +1.5–4.0 LU, 완식 바탕은 같은 시드의 play보다 +0.5–2.5 LU입니다.

### 4.6 포기: 부드럽고 중립 (T = 결말 창이 열리고 `#rv-seal`이 숨은 시각)

- T에 지금 화음이 6초 릴리스를 시작하고, `vi`(Bbm11, A)가 6초 sin으로 들어옵니다. 그 뒤 포기 전이표(`vi` `IV` `ii`)로 산책하며 `I`로 돌아오지 않습니다.
- padIn -2 dB, 컷오프 800 × 테마, 공기 +1 dB(비가 조금 더 들림). 모두 6초 xfade입니다.
- T부터 T+8초까지 건반이 없고, 그 뒤 gaveup 건반을 씁니다.
- 숨결이나 상승은 없습니다. 목표(C6–C7): 최고점은 바탕 +1.5 LU 이하, 포기 바탕은 play ±1.0 LU입니다.

### 4.7 다시 열기, 메뉴판 복귀

- `정답 다시 보기`로 결말 창을 다시 열면 도입 시퀀스 없이 해당 바탕으로 6초 크로스페이드합니다(C8: 상승 +1.5 LU 이하).
- `메뉴판으로` 버튼은 8초에 걸쳐 menu로, `닫고 기록 보기`는 8초에 걸쳐 play로 갑니다. 게임이 끝난 뒤의 기록 화면도 읽는 화면이기 때문입니다.

### 4.8 테마: 오후(개점 전)와 자정

| | 오후 (밝은 화면) | 자정 (어두운 화면) |
| --- | --- | --- |
| 패드 컷오프 배수 | × 1.0 | × 0.88 (조금 더 어둡게) |
| 밤비 층 | 꺼짐 | 켜짐 (-4 dB) |
| 건반 리버브 send | -4 dB | -2 dB |

두 테마 모두 5장의 목표를 각각 통과해야 하고, 같은 장면에서 두 테마의 통합 음량 차이는 1 LU 이하입니다(실측 0.2–0.3 LU).

### 5.4 기본 음량과 조절 범위

- 기본 userVol은 1.0(= 위 목표)입니다. API 범위는 0–1이고 1을 넘겨 키울 수 없습니다. 그래서 위 목표는 어느 음량에서나 상한으로 성립합니다.
- 왜 -29 LUFS인가: 스트리밍 음악(-14 LUFS) 기준으로 맞춘 기기 볼륨에서 약 15 LU 낮게 들립니다. 조용한 방에서는 또렷하고, 소음 속에서는 사라지는 '깔리는' 높이입니다.
  처음에는 -31로 잡았지만, 휴대폰 스피커 손실(약 3.5 LU)을 빼면 실제로는 -34 LUFS 수준이라 너무 희미하다고 판단해 2 LU 올렸습니다.
- 실제로 조절하는 손잡이는 `MASTER_TRIM_DB` 하나입니다. 오너가 들어 보고 "조금 크다" 하면 -2 dB, "안 들린다" 하면 +2 dB를 줍니다. 다른 목표는 상대값이라 함께 움직입니다.

## 6. 사용자 경험

### 6.1 기본은 켜짐

- 오너가 원한 것은 음악이 있는 분위기입니다. 꺼진 채로 시작하면 대부분의 플레이어는 음악이 있다는 것조차 모릅니다.
- 대신 놀라게 하지 않습니다. 첫 사용자 동작 전에는 AudioContext를 만들지도 않고, 동작이 있으면 10초 동안 무음에서 sin² 곡선으로 올라옵니다.
- 끄면 그 선택을 기억하고, 다시는 켜진 채로 시작하지 않습니다.

### 6.2 시작 (자동 재생 정책)

- `document`에 캡처 단계로 `pointerdown`, `keydown`, `touchend`, `click`(passive) 리스너를 겁니다.
- 핸들러 안에서 **동기적으로** 다음을 합니다. await 뒤에 하면 iOS가 허락하지 않습니다.
  1. (처음이면) `navigator.audioSession.type = 'ambient'`를 지원할 때 설정합니다.
  2. `new AudioContext({ latencyHint: 'playback' })`를 만듭니다. sampleRate는 지정하지 않습니다.
  3. `ctx.resume()`을 부르고, 1프레임짜리 무음 버퍼를 재생합니다(iOS 잠금 해제 관례).
  4. 엔진을 만들고 `fade(1, 10)`을 겁니다.
- `ctx.state === 'running'`이 확인되면 리스너를 뗍니다. Safari는 `pointerdown`으로는 풀리지 않을 수 있으므로, 실행 상태가 될 때까지 네 이벤트 모두에서 다시 시도합니다.
- 동작이 스피커 버튼에서 일어났으면 이 리스너는 아무것도 하지 않고 버튼 핸들러가 결정합니다.

### 6.3 스피커 버튼

모듈이 페이지의 `.theme-btn`마다 바로 **앞**에 하나씩 넣습니다(메뉴판 `.topnav-end`, 플레이 바 `.tb-right`). 테마 버튼은 늘 있던 맨 끝 자리를 지킵니다.

```html
<button type="button" class="icon-btn music-btn" aria-pressed="true" aria-label="배경음악" title="배경음악 끄기">
  <svg class="i-on" viewBox="0 0 24 24" aria-hidden="true"><path d="M4 9.5h3.2L12 5.6v12.8l-4.8-3.9H4z"/><path d="M15.5 9.2a4 4 0 0 1 0 5.6"/><path d="M18.2 6.8a7.4 7.4 0 0 1 0 10.4"/></svg>
  <svg class="i-off" viewBox="0 0 24 24" aria-hidden="true"><path d="M4 9.5h3.2L12 5.6v12.8l-4.8-3.9H4z"/><path d="M16 9.6l4.6 4.8M20.6 9.6L16 14.4"/></svg>
</button>
```

- 이름은 항상 `배경음악`이고 상태는 `aria-pressed`(켜짐 true, 꺼짐 false)로 전합니다. 툴팁(`title`)은 켜졌을 때 `배경음악 끄기`, 꺼졌을 때 `배경음악 켜기`입니다.
- 두 버튼은 늘 같은 상태입니다. 하나를 누르면 둘 다 바뀝니다.
- 모양은 기존 `.icon-btn` 규칙(40×40, 아이콘 20px, 선 1.75, 둥근 끝)을 그대로 따릅니다. 모듈이 넣는 스타일은 이것뿐입니다.

```css
.music-btn .i-off { display: none; }
.music-btn[aria-pressed="false"] .i-on { display: none; }
.music-btn[aria-pressed="false"] .i-off { display: block; }
.music-btn[aria-pressed="false"] { color: var(--muted); }
@media (max-width: 359px) { .music-btn { width: 36px; height: 36px; } }
```

- 켜기: 컨텍스트 resume 뒤 4초 페이드인. 끄기: 1.2초 페이드아웃(τ 0.3) 뒤 `ctx.suspend()`. 컨텍스트는 닫지 않습니다(iOS에서 다시 잠금 해제가 필요해짐).
- 결말 창이 열려 있는 동안에는 뒤쪽 화면이 `inert`라 버튼을 누를 수 없습니다. 창은 잠깐 열리는 것이고 닫으면 바로 닿으므로 그대로 둡니다.
- 전역 단축키는 두지 않습니다. 플레이어가 질문을 입력하는 화면이라 충돌 위험이 큽니다.

### 6.4 음량 조절 UI는 두지 않음

이 페이지에는 음악 말고 다른 소리가 없습니다. 그래서 기기나 탭 볼륨이 곧 음악 볼륨이고, 페이지 안의 음량 단계는 같은 일을 두 번 하는 셈입니다.
버튼 하나만 두는 쪽이 플레이 바를 좁게 지킵니다. 엔진에는 `setVolume(0–1)`이 있어 나중에 붙일 수 있지만, 이번 판에는 UI도 저장도 없습니다.

### 6.5 저장

- localStorage 키 `sea-turtle-soup:music`에 `'on'` 또는 `'off'`를 저장합니다. 기존 `sea-turtle-soup:theme`와 같은 꼴입니다. 값이 없으면 `'on'`으로 봅니다.
- 읽기와 쓰기는 모두 try/catch로 감쌉니다. 아티팩트 iframe이나 사생활 보호 창에서는 저장소가 막혀 있을 수 있습니다.

### 6.6 탭을 떠날 때

- `visibilitychange`로 숨겨지면 1.2초 페이드아웃 뒤 `ctx.suspend()`하고 스케줄러를 멈춥니다. 숨은 탭에서는 CPU를 쓰지 않습니다.
- 다시 보이면 `ctx.resume()` 뒤 4초 페이드인합니다. resume이 거부되면(iOS) 6.2의 리스너를 다시 겁니다.
- `pagehide`면 즉시 suspend, `pageshow`(bfcache 복귀)면 보일 때와 같게 처리합니다.
- 컨텍스트가 멈춰 있는 동안 시간도 멈추므로 예약된 음은 그 자리에서 이어집니다.

### 6.7 prefers-reduced-motion

바꾸지 않습니다. 이 설정은 시각적 움직임(전정 자극)을 줄이려는 것이고, 소리는 해당하지 않습니다. 음악을 원하지 않는 사람은 스피커 버튼으로 끕니다.

### 6.8 모바일 Safari

1. `navigator.audioSession.type = 'ambient'`(Safari 16.4 이상): 무음 스위치를 따르고, 사용자가 듣던 음악을 끊지 않고 섞입니다. 배경음악으로 맞는 동작입니다.
2. 잠금 해제는 `touchend` 또는 `click` 핸들러 안에서 동기적으로 `resume()`과 무음 버퍼 재생으로 합니다.
3. `state`가 `'interrupted'`(전화, Siri)나 `'suspended'`가 되었는데 켜짐 상태면 `statechange`에서 리스너를 다시 겁니다.
4. sampleRate를 강제하지 않습니다(예전 iOS는 하드웨어 레이트와 다르면 소리가 깨짐). 컨텍스트를 새로 만들거나 닫지 않습니다.
5. `webkitAudioContext` 대체를 지원합니다. `createStereoPanner`가 없으면 패닝 없이 갑니다.
6. Safari는 `setValueCurveAtTime` 구간이 같은 AudioParam의 다른 이벤트와 겹치면 예외를 던집니다. 곡선은 화음과 드론 엔벨로프에만 쓰고(어택과 릴리스가 겹치지 않도록 릴리스 시작 ≥ 어택 끝), 장면 파라미터에는 `setTargetAtTime`만 씁니다.

### 6.9 CPU와 배터리 예산

| 항목 | 상한 |
| --- | --- |
| 살아 있는 OscillatorNode | 50개 (패드 3화음 × 4성부 × 2 = 24, 드론 2 × 2 = 4, 건반 8 × 2 = 16, LFO 6: 와우 1, 컷오프 1, 드론 진폭 2 × 2) |
| 건반 동시 발음 | 8 |
| 패드 동시 화음 | 3 |
| 오디오 버퍼 메모리 | 8 MB 이하 (노이즈 모노 29.1초 약 5.6 MB + 임펄스 약 1.3 MB, 48 kHz 기준) |
| 스케줄러 | setTimeout 200 ms 간격, 1.5초 앞까지 예약. 숨김이나 꺼짐 상태에서는 정지 |
| 금지 | AnalyserNode, ScriptProcessorNode, AudioWorklet, requestAnimationFrame |
| 렌더 속도 | 오프라인 100초 렌더가 이 컨테이너 Chromium에서 실시간의 8배 이상 (프로토타입 약 10배) |

모든 노드는 끝나면 stop하고 disconnect합니다. 한 시간이면 건반만 수백 음이므로, 정리하지 않으면 메모리가 샙니다.

### 6.10 AudioContext가 없을 때

- `window.AudioContext || window.webkitAudioContext`가 없으면 버튼을 넣지 않습니다. `STSMusic.supported = false`이고 아무 일도 하지 않습니다.
- 생성이나 resume이 실패하면 `console.info`로 한 번만 남기고 조용히 물러납니다. `console.error`와 `console.warn`, 잡히지 않은 예외는 금지입니다. 게임이나 스모크 테스트를 깨면 안 됩니다.
- 모듈 전체를 try/catch로 감쌉니다. 음악이 실패해도 게임은 그대로 동작해야 합니다.

### 6.11 접근성

- WCAG 1.4.2(오디오 제어): 소리는 사용자 동작 뒤에만 나고, 페이지 첫 내비게이션 바에 끄는 버튼이 있습니다.
- 스크린 리더 사용자는 음악과 음성 안내가 겹칠 수 있습니다. 그래서 음량이 낮고 끄기는 한 번이며, 그 선택을 기억합니다.

## 7. 엔진 구조

### 7.1 파일과 포함 방법

- 원본은 `web/public/music.js` 하나입니다. 의존성이 없는 IIFE이고 `'use strict'`를 씁니다. 크기는 압축 전 40 KB 이하로 둡니다.
- 웹 서비스판: `web/public/index.html`의 `</body>` 바로 앞에 `<script src="music.js" defer></script>`를 넣습니다.
- 아티팩트판: `index.html`의 `</body>` 앞에 `<!-- sts-music:begin --><script id="sts-music">…music.js 내용…</script><!-- sts-music:end -->`를 넣습니다.
  `web/tools/sync-music.js`가 표시 사이를 원본으로 덮어씁니다. 두 사본이 바이트 단위로 같은지 테스트가 확인합니다(U12).
- 게임 코드는 바꾸지 않습니다. 모듈이 DOM을 관찰합니다.

### 7.2 공개 API

```js
window.STSMusic = {
  version: '1.0.0',
  supported,                        // AudioContext 사용 가능 여부
  TABLES,                           // 화음·전이·장면·레벨 표 (Object.freeze, 테스트용)
  Composer,                         // 소리를 모르는 순수 생성기
  Engine,                           // Web Audio 그래프 (BaseAudioContext 어디서나)
  render,                           // 오프라인 렌더 도우미
  controller,                       // 페이지 컨트롤러 인스턴스 (자동 시작 시), 아니면 null
};

const e = new STSMusic.Engine(ctx /* AudioContext | OfflineAudioContext */, {
  seed: 1,                          // uint32. 같은 시드와 같은 타임라인이면 같은 소리
  destination: ctx.destination,
  scene: 'menu',                    // 'menu' | 'play' | 'thinking' | 'solved' | 'gaveup'
  theme: 'night',                   // 'night' (자정, 어두운 화면) | 'day' (오후, 밝은 화면)
  volume: 1,                        // 0–1
  fadeIn: 10,                       // 시작 페이드인 초. 0이면 없음
  trimDb: 2.9,                      // MASTER_TRIM_DB
  solo: null,                       // 분석용: 'pad' | 'drone' | 'keys' | 'texture'
});
e.start(at = ctx.currentTime);
e.setScene(name, { at, intro = true });   // intro:false면 결말 도입 시퀀스 생략 (다시 열기)
e.cue('chapter', { at });
e.setTheme('night' | 'day', { at });
e.setVolume(v, { at, seconds = 1 });
e.fade(to /* 0–1 */, seconds, at);        // 켜기·끄기·탭 전환용 마스터 페이드
e.scheduleUntil(t);                       // t 이전의 모든 음악 이벤트를 생성하고 예약
e.dispose(at);                            // 모두 릴리스하고 꼬리가 끝나면 disconnect
e.state;                                  // { scene, theme, chord, voices, notes } 읽기 전용 스냅샷

const buf = await STSMusic.render({       // OfflineAudioContext(2, sr*duration, sr) 위에 같은 Engine
  seed: 1, duration: 100, sampleRate: 48000, theme: 'night', fadeIn: 10, solo: null,
  events: [ { t: 0, scene: 'play' }, { t: 40, cue: 'chapter' }, { t: 60, theme: 'day' } ],
});                                       // → AudioBuffer
```

- `setScene`, `cue`, `setTheme` 호출은 `at`이 줄어들지 않는 순서여야 합니다. 오프라인에서는 모든 제어를 먼저 등록하고 `scheduleUntil(duration)`을 한 번 부른 뒤 `startRendering()`합니다. 그래서 실시간과 오프라인이 같은 경로를 탑니다.
- `render()`는 events의 첫 장면으로 엔진을 만들고, 나머지를 순서대로 등록하고, `scheduleUntil(duration)` 뒤 렌더링합니다.

### 7.3 세 부분

1. **Composer** (순수, Web Audio 없음): 시드와 제어 타임라인(장면, 큐, 테마)을 받아 시간 순서대로 이벤트를 냅니다.
   - 이벤트 종류: `{type:'chord', t, id, voicing, att, hold, rel}`, `{type:'release', t, chordId, rel}`, `{type:'drone', t, root, att}`, `{type:'droneRelease', t, rel}`, `{type:'note', t, midi, vel, pan}`, `{type:'tex', t, layer, db, tau}`, `{type:'rate', t, layer, ch, value, ramp}`
   - 릴리스를 별도 이벤트로 두면, 장면이 바뀔 때 아직 오지 않은 릴리스 시각을 당길 수 있습니다.
   - 오디오 없이 60분을 몇 초 만에 돌릴 수 있어 8.3의 반복·밀도 검사에 씁니다.
2. **Engine**: 3장의 그래프를 만들고, Composer 이벤트를 노드와 자동화로 바꾸고, 장면 파라미터 크로스페이드(4.2)와 큐 자동화(4.4–4.6)를 겁니다.
3. **Controller** (페이지 전용): 버튼 삽입, 저장, 첫 동작 잠금 해제, DOM 관찰과 장면 판정(4.1), 탭 전환, 실시간 스케줄러를 맡습니다.
   테스트용으로 `controller.history`에 `{t, kind: 'scene'|'cue'|'theme'|'state', value}`를 최근 200개까지 남깁니다.
   자동 시작 조건은 `#menu-view`가 있고 `window.STS_MUSIC_AUTOSTART !== false`일 때이며, DOMContentLoaded 이후에 시작합니다.

### 7.4 실시간 스케줄러

- 200 ms마다 `scheduleUntil(ctx.currentTime + 1.5)`를 부릅니다. 컨텍스트가 `'running'`이 아니면 건너뜁니다.
- 제어 시각이 이미 생성된 구간 안이면 화성과 건반 변화는 구간 끝으로 미룹니다(4.2). 파라미터 자동화는 요청 시각에 바로 겁니다.

### 7.5 파라미터 추적

`cancelAndHoldAtTime`은 Firefox에 없으므로 쓰지 않습니다. Firefox의 `AudioParam.value`는 자동화 중인 현재 값을 돌려주지 않을 수 있습니다.
그래서 엔진이 장면 파라미터마다 마지막 자동화(시작값, 목표, 시작 시각, τ 또는 선형 끝)를 기억하고,
`trackedValue(T) = target + (v0 - target) * exp(-(T - t0) / τ)`로 그 시각 값을 계산해 4.2의 `setValueAtTime`에 씁니다.

### 7.6 노드 수명

화음, 드론, 건반 음은 각자 끝나는 시각에 stop하고 `onended`에서 하위 노드까지 disconnect합니다. 공기 소스, LFO, 리버브는 엔진이 살아 있는 동안 유지합니다.
`dispose()`는 모두 2초에 걸쳐 내린 뒤 해제합니다.
